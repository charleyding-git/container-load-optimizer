# 配置文件规范（config.json）

## 顶层结构

```json
{
  "container": "40HQ",
  "pallet": "US48",
  "custom_pallet": null,
  "constraints": { ... }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `container` | string | 柜型代码，见 `references/container_specs.md` |
| `pallet` | string | 托盘代码；`CUSTOM` 时需填 `custom_pallet` |
| `custom_pallet` | object\|null | `{L, W, H}` 单位 mm |
| `constraints` | object | 见下 |

## constraints 全字段

```json
{
  "mode": "pallet",
  "mono_sku": false,
  "allow_top": true,
  "allow_double_pallet": false,
  "tihi_layers": null,
  "max_pallet_stack_h": null,
  "max_pallet_weight": null,
  "min_support_ratio": null,
  "repair_support": true,
  "max_cog_offset": 0.15,
  "stack_pattern": "auto",
  "load_order": "auto",
  "optimize": "containers",
  "seed": 0,
  "restarts": 12
}
```

| 字段 | 默认 | 硬/软 | 说明 |
|---|---|---|---|
| `mode` | `"pallet"` | 硬 | `pallet` 有托盘 / `nopallet` 无托盘货垛柱。`nopallet` 时托盘相关约束（`mono_sku`/`allow_top`/`allow_double_pallet`/`tihi_layers`/`max_pallet_stack_h`/`max_pallet_weight`）自动失效；有效堆高取**门开口高**（无托盘货箱需逐箱过门） |
| `mono_sku` | `true` | **硬** | 一托一 SKU。`false` 允许层间混装（托盘填充率更高、柜数更少，但需贴 Mixed SKU 标签） |
| `allow_top` | `true` | 软 | 托盘顶部平躺散放。利用顶部剩余高度，自动优化模式可放宽 |
| `allow_double_pallet` | `false` | **硬** | 双层托盘（一个托盘上再放一个托盘）。涉及叉车作业与收货区高度 |
| `tihi_layers` | `null` | **硬** | TiHi 带板层数 1~4，对应货高上限 1800/1200/800/600mm（含托盘） |
| `max_pallet_stack_h` | `null` | **硬** | 收货区托盘货物限高 mm（含托盘）。超过货架/收货区高度会被拒收 |
| `max_pallet_weight` | `null` | **硬** | 单托毛重上限 kg。Amazon FBA 为 500 |
| `support_policy` | `"relaxed_all"` | — | 支撑率策略 `relaxed_all`/`balanced`/`strict`，见下节。**默认放任** |
| `reorder_layers` | `false` | 软 | 层序优化：支撑不佳的层挪到托盘上部。可消除完全悬空，代价是多 1 个柜 |
| `min_support_ratio` | `null` | **硬** | 垂直支撑率下限（求解阶段）。一般保持 null，由 `support_policy` 统一控制 |
| `repair_support` | `true` | 软 | 求解后定向修复支撑率风险（保留层序，只重排 2D 布局） |
| `max_cog_offset` | `0.15` | 软 | 整柜重心横向偏移上限（占柜宽比例）。超限报警告 |
| `stack_pattern` | `"auto"` | 软 | `column` 重叠式 / `interlock` 交错式 / `auto` |
| `load_order` | `"auto"` | 软 | `heavy_first` / `height_desc` / `sku_group` / `auto`（当前仅排序提示，不做路径优化） |
| `optimize` | `"containers"` | — | `containers` 柜数最少 / `strict` 严格按设定 |
| `seed` | `0` | — | 随机种子。改 seed 会得到不同（但等价质量）方案 |
| `restarts` | `12` | — | 求解轮数。越大越稳越慢；12 轮约 3 秒，24 轮约 6 秒 |
| `max_containers` | `null` | **硬** | 柜数硬上限（**按批次限定**）。设 7 → 若某批次求解出 >7 柜，最末柜整柜溶解，其箱作为「柜底裸地散箱」分摊进前 7 柜的柜底裸地（绝不增柜、箱数守恒）。`null`=不限制 |

## 支撑率策略（support_policy）—— 三档

支撑率是几何指标（支撑面积占比）。**它不是风险的直接度量** —— 实测推导：

- 纸箱短时悬空**不会**失效：抗弯余量实测 100~50000 倍，重心也不出支撑面
- 真正失效有两个独立机制：
  1. **载荷路径断裂**（支撑率 = 0%）：载荷无处传递 → 整箱必坠落，**与重量无关**
  2. **局部压溃**（部分支撑）：承压需求 > 承压能力时压溃
     - 承压需求 = 该箱承受的上方累积载荷（自顶向下按重叠面积传播）
     - 承压能力 = BCT(纸箱抗压强度) × 支撑面积比例
     - **轻抛货天然低风险**：8kg/箱 40% 支撑率仍有 9.7 倍余量；
       90kg/箱 40% 支撑率时余量降至 1.4 倍，3 层就压溃

因此三档策略：

| 策略 | 求解期行为 | 校验期行为 | 实测（7SKU/4935箱/40HQ） |
|---|---|---|---|
| `relaxed_all` | 只修「完全悬空」 | 支撑率不达标 → **info**（外部加固兜底） | **7 柜 / 66.0%** |
| `balanced` | 修支撑率 < 55% 的层 | 支撑率不达标 → info | 8 柜 / 57.7% |
| `strict` | 支撑率硬约束，绝不放宽 | 同上 | 8 柜 / 57.7%（慢 40 倍） |

**默认 `relaxed_all`** —— 按你的判断：支撑率不作为硬约束触发修复，倾向外部手段（缠绕膜/捆扎）兜底。
但「完全无支撑」无条件强制修复 —— 那是物理硬伤（轻抛货也会掉），不能靠缠绕膜解决。

### 「放不满的层」置顶（自动，无需开关）

已内置为**层构建的固定规则**：某层因余量不足只放了少量箱、没铺满托盘面时，
自动挪到托盘最上层 —— 因为它若排在中间，上层箱就有一部分悬空（会掉）。
挪到顶上则无害（上方无物，下方层完整铺满 → 支撑率 100%）。

判据用**底面积覆盖率**（≥85% 视为铺满），**不是 `n < cpl`** ——
后者会误判：cpl=4 的 428×423 箱放 4 个只铺了 856×846，而托盘面是 1219.2×1016。

实测效果：完全悬空托盘 3→1，支撑率 info 级从 47 降到 12，**柜数不变（7 柜）**。

### 层序优化（reorder_layers）

把「支撑不佳的层」尽量挪到托盘上部。物理依据：上层箱承受的上方累积载荷小 → 压溃风险低；
顶层即使有悬空，上方无物也不会把下层带塌。

实测效果：**可消除全部「完全悬空」（3 → 0）**，代价是**多 1 个柜**（7→8）。
层序调整会打乱原本整齐的层序 → 每托装箱量下降 → 多开托盘，故只对确有支撑问题的托盘启用。

### 重量分级（自动）

| 密度 kg/m³ | 分级 | 支撑风险 |
|---|---|---|
| < 100 | 轻抛货 | 低 —— 自重不足以压溃下层，靠缠绕膜/捆扎兜底即可 |
| 100~300 | 常规货 | 中 —— 按层载荷核算承压余量，支撑率不足需提示 |
| 300~600 | 偏重货 | 高 —— 易压溃下层，必须显性提示并调整层序 |
| ≥ 600 | 密度货 | 极高 —— 严格控制支撑率与层数，重箱置底并逐层核算 |

**单箱重量缺失**时按体积密度兜底估算，并在报告中提示「重量未提供，结论仅供参考」。

### 校验判级

| 代码 | 级别 | 含义 |
|---|---|---|
| `LOAD_PATH_BROKEN` | warn | 存在完全无支撑的箱（必坠落）——已自动重排，需人工复核 |
| `BEARING_OVERLOAD` | error | 承压需求 > 承压能力（会压溃） |
| `BEARING_MARGIN_LOW` | warn | 承压余量 < 60% |
| `SUPPORT_RATIO_LOW_INFO` | info | 支撑率低于 75% 但承压余量充足 —— 外部加固兜底 |
| `SUPPORT_RATIO_LOW` | warn | 支撑率低于 75% 且承压余量不足 |
| `HEAVY_CARGO_NOTICE` | info | 含重货 —— 显性提示（按密度分级） |
| `WEIGHT_MISSING` | warn | 单箱重量未提供 —— 承压结论仅供参考 |

## 硬约束 vs 软约束

**硬约束**：求解器绝不产出违反的解。若导致无解，会放宽**支撑率**并降级为警告（唯一会降级的约束），其余直接无解。

**软约束**：自动优化模式下可放宽，但会在方案说明与校验报告中显式列出。

**`optimize` 的作用**：
- `containers`（自动优化）：优先最少柜数，软约束可放宽
- `strict`（严格按设定）：硬约束绝不违反，即使多几个柜

## 层高与门高

**门开口高是硬约束，不是柜内高。**
- 40HQ：内高 2698mm，门开口 2585mm → 货垛实际可用 2585mm
- 40GP：内高 2393mm，门开口 2280mm
- 货垛高度 = 托盘高(145) + 货体高，必须 ≤ 门开口高

超过门开口高的货垛在实际作业中**无法拉入柜门**，这不是理论问题。

## 柜底裸地利用（bare floor）

**背景**：40HQ 铺满 21 个美标托盘（1219.2×1016mm）后，柜底面积 28.30 m² 被占 26.01 m²，
剩约 **2.29 m²（8.1%）** —— 但这是被 21 个托盘边缘切出来的**狭长碎条**，并非完整空地。
在 7 柜装法里托盘已从柜门端（x=0）一直铺到箱头端（x≈11988，柜长 12032），**柜门端 gap=0**，
所以「柜门端裸地」实际不存在；真正的裸地是**托盘之间的内部缝隙**。

**机制**（`max_containers` 触发）：

1. 正常求解产出 N 个柜；若某批次 N > `max_containers`，则**最末柜整柜溶解**（取出其托盘上的箱）。
2. 溶解出的箱作为**裸地散箱**（`kind="bare"`），用 `floor_free_rects` 算出前 N 柜的柜底自由区，
   逐柜、逐箱落位 + **3D AABB 重叠检测**（公差 0.6mm），均匀分摊（带缺口顺延，不丢箱）。
3. 裸地箱**直接落柜底（无托盘）** → 底层支撑率 100%；顶部仍受门开口高约束。
4. `validator._check_bare_overlap` 按柜校验裸地箱互不重叠；`export_viz` 以**橙色虚线描边**渲染裸地散箱并加图例。

**守恒**：溶解箱数 = 裸地放置数，残留由箱数守恒门禁暴露（说明 `max_containers` 设得过小，该批真实装不下）。

**注意**：裸地只填补内部缝隙。订单量固定（如批次1 恰好 4935 箱），无多余货去填满全部 2.29 m²/柜
的内部裸地 —— 这是订单量决定的，**不是算法遗漏**。`max_containers` 的意义是把「本会逼出第 8 柜的溢出箱」
吸收进前 7 柜的裸地，从而**守住柜数上限**。

## 校验门禁

| 级别 | 含义 | 后果 |
|---|---|---|
| `error` | 硬错误 | **禁止交付**，退出码 1 |
| `warn` | 需注明 | 可交付，但方案说明必须列出 |

L1 几何 error：出托盘、出柜壁、箱互不重叠、托盘互不重叠、超门高、装载率>100%、尺寸非法
L2 error：单托超重、堆码层数超限、支撑率<50%（塌垛风险）
L2 warn：支撑率<75%、托盘承载利用率<80%、重心偏高、整柜重心偏移>15%
L3 error：plan↔xlsx↔3D 三方数值不一致、配色不一致
